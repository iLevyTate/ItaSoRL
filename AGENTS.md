## Learned User Preferences

- All markdown a person reads (posts, README, site/Colab copy, outreach, FINDINGS, specs, preregistration prose) follows Strip the AI Tells. Keep numbers, tables, and `[0:00]` cue lines. No em/en dashes, no "not just X it's Y," no participial tails, no Moreover/Furthermore/Additionally, no rule-of-three padding, no summary ending. Banned filler words stay banned. Do not swap in a synonym. Scientific "robust" (a result that holds under a named check) stays; marketing "robust" does not.
- Keep outreach and article drafts unpublished unless explicitly asked; PRs should not publish post content. Uploading media (videos, gifs) can go ahead without the accompanying post copy going live.
- The paper never goes to the ITASORL `main`: the LaTeX manuscript (`docs/paper/`, gitignored by `paper/`) and anything generated for it (tables from `scripts/build_paper_tables.py`, which writes to the gitignored `docs/paper_tables/`, never inside `docs/paper/`) are not committed or pushed from this repo. The manuscript lives in its own paper repo checkout, and edits to it are expected to be committed and pushed there with a rebuilt PDF. Checks that touch the manuscript must work without it in CI.
- Visualizations, film clips, and the explanations and branding language around them should read for a general audience and designer handoff, not only researchers. Prefer plain English.
- For wide and vertical clips, distribute on-screen information to fill empty space in a design-focused way rather than leaving sparse unused regions. Scale type size and format so the frame reads as full. Labels must not overlap nodes or each other, and the panel title, meter, verdict readout, and first node label need clear gaps between them.
- Prefer LinkedIn and YouTube Shorts for distribution; keep X/Twitter presence low-interaction when used.
- For each film clip, draft channel-specific posts (LinkedIn, X, YouTube Shorts, and relevant Reddit communities) in the user's first-person voice using writing-social-voice plus Strip the AI Tells; open with the claim, relate the clip to ML/AI, and do not use identical cross-posts. Treat clips as a short series posted over time, and include a brief refresher of earlier clips. The 90s full film is the watch-this-one post (voice and music in). LinkedIn uses uneven paragraphs, not one idea per line.
- In Colab setup, let the user choose hardware; do not default to T4.
- For loop gifs and looping film clips, animations should start and end on the same frame so they loop cleanly.
- Prefer cinematic clip animation that shows the agent or creature in action, not only abstract graph motion; for story-arc deliverables, provide a continuous VO script and second-by-second event timeline so VO and music can be recorded in one take.
- Deliver VO and music as separate tracks, and keep on-screen narration text out of clip builds because the user records VO himself. Node labels, group labels, panel titles, and verdict readouts stay on screen. For Suno, use v5.5 Advanced as in the 2026-08-12 hub guide: watch the target video first, write a specific Style paragraph (genre, BPM, instruments, what each section does), put `[Intro]` / `[Verse]` / `[Chorus]` / `[Outro]` plus `[0:00]` picture clocks in Lyrics (all bracketed, Instrumental on), Exclude vocals and trailer hits, Weirdness 50, Style Influence Strong. Official tries: Create (two takes), Create again with a slight Style tweak, one slider try, then Remaster Subtle/Normal on the keeper. No Style wand. No Voices. Default felt piano / warm pad / tape hiss. A named STYLE keeps the same clocks. For Hume VO, use the saved custom voice `Tankside` from `artifacts/clip_audit/post-materials/hume-voice.md`; output one pasteable text block with `[pause]` / `[long pause]` whose spoken length matches the video duration (VO may exceed 1000 characters). Acting `description` stays under 100 characters. Default speed 0.9. Bracketed cue lines carry musical direction and BPM only, no scene description.
- Verify a deliverable before calling a build done. Confirm every output decodes cleanly and has the expected duration instead of trusting container metadata or a zero exit code.

## Learned Workspace Facts

- ITASORL studies when RL agents internally represent environment distinctions they were not trained to care about.
- Primary end-to-end run output belongs under `fullruns/` (see `itasorl/results_io.py`). The Colab GPU workflow lives in `notebooks/colab_gpu.ipynb`; runs should persist results to Google Drive and locally.
- Public site is GitHub Pages at `https://ilevytate.github.io/ItaSoRL/`; CI mirrors `main` onto `gh-pages`.
- `assets/film/` is gitignored by default and allowlisted by name in `.gitignore`. Every master, clip, partial, vertical cut, textless pass, and loop gif is a local build output: rebuild with `viz/player/capture/build-two-minds.ps1`, do not commit it. The remote carries only the five files the site serves: the two 720p web encodes, their two posters, and `README.md`. The four July demo loops were retired from the site on 2026-10-10 and are no longer allowlisted. A new film output is therefore ignored automatically, with no `.gitignore` edit needed; to publish one, add an explicit `!` line for it. Note that `assets/film/` cannot be ignored as a directory, because git refuses to re-include a file whose parent directory is excluded, so the rule is the glob `/assets/film/*`. Editing masters (`.mov`, `.mkv`, `.avi`) and NLE project files are ignored repo-wide.
- Interactive player and clip capture tooling live under `viz/player/`. The film player uses `?layout=vertical` for the 9:16 cut. Capture of the recorded world must serve from `viz/` so `data/scene.json` is reachable; serving `viz/player/` alone hides the scene file and falls back to the placeholder world.
- The site's `index.html` is generated: edit `index.template.html`, then run `python scripts/build_index.py`. CI (`scripts/audit_stats_recheck.py`) fails if the rendered page is stale.
- Film one is *Detectable All Along* (the 90 s story). Its voiced master, `ItasorlOverview.mov` (DaVinci Resolve export, 1920x1080, AAC), was released 2026-08-24 and lives on the owner's Google Drive, not in git. The site serves the 720p web encode `assets/film/detectable-all-along-web.mp4`; the captions-only cut plays live at `viz/player/`. The silent 9:16 master of that cut stays local and gitignored: `viz/player/capture/build-detectable-vertical.ps1` writes `assets/film/detectable-all-along-vertical.mp4` plus its poster, and the `assets/film/` allowlist keeps both out of git. Only the build tooling goes on the remote, so re-render instead of committing the output.
- Film two is *Two Minds* (the labeled brain film). Renderer: `viz/player/brain/`; rebuild: `viz/player/capture/build-two-minds.ps1`; site encode: `assets/film/two-minds-web.mp4`. The 66 s tour opens on a 9.5 s title card and closes on a 6 s end card, both rendered as ordinary chapters of `viz/player/brain/` and trimmed by reading time, so the web encode already carries its intro and outro. No voiced cut of Two Minds is committed; if one is produced, replace the web encode in place. Provenance for every film file: `assets/film/README.md`. The build script takes an exclusive single-run lock and decode-checks each output, because two concurrent runs write the same filenames and silently shred the H.264 payload of every clip while the container metadata still looks valid. The renderer `viz/player/brain/brain.js` gates the narration band and headline caption behind a `caption=1` query flag, so labeled builds, which omit that flag, ship labels with no on-screen narration.
- ffmpeg invocations in PowerShell need `-nostdin`. Without it ffmpeg consumes stdin and silently ends the enclosing loop after the first iteration, with a zero exit code.
- Reusable agent prompt for clip music lives at `artifacts/clip_audit/post-materials/suno-music-agent-prompt.md`. Hume series voice and VO agent prompt live at `artifacts/clip_audit/post-materials/hume-voice.md`.
- `docs/paper/` is its own git checkout of the private paper repo (`https://github.com/iLevyTate/itasorl-paper.git`, branch `main`) nested inside the ITASORL tree. The manuscript targets TMLR under double-blind review, with JMLR as the fallback. After a manuscript edit, commit and push there and rebuild the tracked `docs/paper/main.pdf`. `python scripts/build_paper_tables.py --manuscript docs/paper` audits the manuscript wording against the committed record and should report 0 items to review. CI (`scripts/audit_stats_recheck.py`) recomputes artifact summaries but never reads `main.tex`, so manuscript numbers must be checked against `artifacts/` directly. `docs/paper/make_source_package.py` builds the submission source, flattening the `\input` table files and stripping comments and the author block.
- Saved agents for the corrected L3 runs are local under `fullruns/corrected_l3_h8_wm/` and `fullruns/corrected_l3_h8_nowm/`, so readout-only reruns need no retraining. B1 and B2 confirmation agents are local under `fullruns/balanced_confirmation_wm/` and `fullruns/balanced_confirmation_touch/`. The T-touch and S-immortal runs were trained in a cloud container. Their agents live on origin branches `run/T-touch` and `run/S-immortal`, with a local copy (60 agents each plus quarantined sets) under `fullruns/branch_preserve/run/T-touch/` and `fullruns/branch_preserve/run/S-immortal/`, so readout-only reruns on them need no retraining. Do not re-adjudicate a stored run with a new threshold, estimator, control, or stack, and do not turn a missing or non-finite gate into a pass. The workstation interpreter is Python 3.13.2 with a local NumPy 1.26.4 build; official 1.26.4 wheels stop at Python 3.12, so leave that pin in place when a result claims bit-exact reproduction. Agent weights stay off `main` and every branch of the public remote except nine run and upload branches on origin that already carry saved agents (owner decision recorded 2026-10-17: the repository stays public and Pages stays on during review). Their `.pt` counts, from `git ls-tree -r origin/<branch> --name-only | grep -c '\.pt$'`: `run/T-touch` 156 and `run/S-immortal` 144 (both counts include quarantined files), `run/C1-rerun` 90, `run/C2-rerun` 90, `run/H7-corrected` 60, `run/H8GS2-corrected` 60, `run/H10GS1-corrected` 60, `run/T-gn-h96` 60 and `upload/l1-heldout-agents` 60. Their artifact subtrees are preserved locally in `fullruns/branch_preserve/`. Do not add weights to any other branch. The full pytest suite takes about 15 minutes, and a full 20-cell corrected run takes roughly 6 to 9 hours on the local GPU laptop.
