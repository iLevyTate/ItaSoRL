## Open gaps, in the order I would work them

1. The cross-validation split depends on the software stack. `grouped_auroc`
   (`itasorl/experiment_a.py`) uses `GroupKFold` with one group per episode, and
   older scikit-learn orders equal-sized groups with an unstable `np.argsort`, so
   fold membership depends on the numpy version and probably the CPU. All 60
   per-seed values behind the L3 headline and all 30 in the B-v3 summary are exact
   fold means under the split (24,20), (22,22), (21,23), (21,23), (22,22), which
   scikit-learn 1.5.2 with numpy 1.26.4 reproduces. All 120 values from the two
   cloud runs sit on balanced 22/22 folds, which scikit-learn 1.6.1 with numpy
   2.2.6 and scikit-learn 1.9.1 (stable sort) both produce. This is noise, not
   bias. A simulation at AUROC near 0.73 (300 synthetic datasets, not project data)
   puts the shift at about 0.011 per seed and 0.004 on a 10-seed mean, one standard
   deviation, with no consistent direction. It still breaks bit-exact reproduction
   of every published pooled number on current scikit-learn, and
   `scripts/audit_stats_recheck.py` compares docs with artifacts, so it cannot see
   it. Fix: build folds from a seeded permutation, pin scikit-learn and numpy
   (requirements say `>=1.3` and `>=1.24`), then re-score the saved hidden 8 dumps
   under both splits.

2. Step 2 cannot separate losing the decoder from being a weaker survivor. Its
   train@0.45 eval@0.45 return is -0.474, against -0.219 for the published hidden 8
   agent. `docs/ITASORL.md` names "baseline is tuned fairly" as the key assumption
   for this baseline; the frozen spec ran it on the decoder agent's settings with no
   tuning. Inside the run, the best survivor by engagement return (seed 6, -0.19) is
   the only seed over the bar (0.810), and return against target correlates at
   r = 0.54 (p about 0.11; 0.40 on cross-eval return). Across runs the pattern does
   not hold: the step 4 agents return +0.008 and read 0.639, the hidden 7 agents
   return -0.734 and read 0.737. The run that settles it trains the model-free arm
   until its return reaches about -0.22, then probes.

3. Step 4 changed seed and capacity together and cannot place its size relative to
   the bar. FINDINGS 10.9 now says the magnitude gap to 0.752 has two candidate
   sources the design did not separate (the subtler instance and the CPU device).
   G seed 2 at hidden 8 separates instance from capacity; the frozen fallback never
   reached it because seed 1 produced a passing candidate first.

4. Oracle AUROC does not fix what the organism picks up. G seed 1 at hidden 8 scored
   oracle 0.928, the same as the headline fingerprint, and its untrained floor came
   back at 0.664 against 0.483. FINDINGS 10.9 records this as a finding. It still
   bears on the "matched band" framing of FINDINGS 14.5, whose conclusion holds
   because its noise surrogate had a clean floor (0.448).

5. The step 2 and step 4 state dumps and saved agents were written to the cloud
   container's gitignored `fullruns/`. Only the per-seed cells, results, and
   behavior-audit JSON were committed. Any readout-only follow-up on those agents
   (sensory-echo, a pinned-split re-score, the H2 battery) now needs retraining,
   about four hours of CPU per run. The device-control script copies the same
   small files only, so a rerun of it would lose its dumps the same way.

6. The sensory-echo control has run only at hidden 8. Hidden 7, where the behavior
   control was least clean (untrained residual 0.579, predictor 0.691), is a
   readout-only job on agents already saved locally.
